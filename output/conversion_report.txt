============================================================
 HDR 截图双路导出报告（零第三方依赖，仅用 Go 标准库）
============================================================

[1] 两路导出
  浮点 PPM (PFM): output/scene.pfm
    - PF 魔数，RGB 三通道 IEEE-754 float32，小端，bottom-up 扫描线
    - 原始线性光数据，无 Gamma、无色域/白点元数据，允许 >1 的高光
  8-bit PNG 预览: output/scene_preview.png
    - 8 位 RGB，内嵌 sRGB / gAMA(0.45455) / cHRM / tEXt 块
    - 查看器据此识别像素已完成 sRGB 编码，避免再次套用 Gamma

[2] 场景亮度统计（线性光）
  像素总数      : 256000
  最大亮度      : 9.8458（SDR 白 = 1.0000）
  最大单通道码值: 10.1155
  平均亮度      : 0.2737
  超过 1.0 的像素: 6850 (2.68%)

[3] 转换说明（线性 HDR -> 8-bit sRGB）
  步骤 1 曝光   : L' = L * 1.000
  步骤 2 色调映射: Reinhard  T = L' / (1 + L')，平滑压缩 >1 高光而非硬裁切
  步骤 3 传递函数: sRGB OETF（暗部线性段 + 2.4 次幂段），仅应用一次
  步骤 4 量化   : 四舍五入到 [0,255]
  场景峰值 9.8458 经映射后的最大码值 = 244 / 255

[4] 为什么预览软件可能二次套用 Gamma
  PFM 不携带任何色彩元数据，软件只能按约定把它当作线性光；
  若 PNG 缺少 gAMA/sRGB/cHRM，部分软件会猜测一个 Gamma 再编码一次，
  画面会整体发灰发白（见对比页中段 DOUBLE GAMMA 演示条）。
  本 PNG 显式声明 sRGB，配合 tEXt 记录转换来源，保证 Gamma 只做一次。

[5] Reload 往返校验
  对比图        : output/reload_compare.png
  float32 最大绝对误差: 0
  float32 平均绝对误差: 0
  float32 最大相对误差: 0
  重渲染字节差异数    : 0（最大单通道差 0）
  结论: PFM 往返无损，reload 前后画面字节级一致。
